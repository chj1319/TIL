## git
- git 공간은 크게 4가지로 나눌 수 있음
1. 작업 디렉토리(Working Dir) : 실제 파일 편집 -> git add
2. 스테이징 영역(Staging) : 커밋할 변경 선별 -> git commit
3. 로컬 저장소(.git) : 커밋 이력 보관 -> git push
4. 원격 저장소(GitHub)

## branch
- 브랜치는 main에서 갈라저 나온 독립적인 작업 흐름 

```
git switch -c feature/lidar-driver   # 브랜치 생성 + 이동
# ... 작업, 커밋 반복 ...
git switch main                      # 언제든 main으로 복귀 (작업물은 브랜치에 안전)
```

- main에는 실제 동작하는 코드만 모든 작업은 branch에서 검증 후 main으로 

## merge & rebase
- 브랜치에서 작업을 마치면 main으로 합쳐야 함. 이때 방법은 merge 또는 rebase

![merge_vs_rebase](https://teamsparta.notion.site/image/attachment%3Aac64e621-7fa5-465b-9a69-08807dd8c012%3A04_merge_vs_rebase.png?table=block&id=3ae2dc3e-f514-81e7-a0e3-d85a04afde73&spaceId=83c75a39-3aba-4ba4-a792-7aefe4b07895&width=1410&userId=&cache=v2&imgBuildSrc=requestProxiedImageUrl)

- 공유 브랜치(main)애 기능 합치기 -> merge(PR병합) : 이력 보존, 협업 기록 명확
- 내 로컬 브랜치를 최신 main과 동기화 -> rebase : 지저분한 병합 커밋 없이 깔끔
- 이미 push한 커밋 -> rebase 급지 : 이력 다시 쓰면 팀원 이력과 충돌

-> rebase는 로컬 커밋에서만 씀
